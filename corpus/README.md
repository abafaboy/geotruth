# geotruth corpus

The inputs geotruth poses to geometry libraries, and the exact answers to them.

The case data and the expected answers in this directory are dedicated to the public domain
under **CC0 1.0** ([LICENSE](LICENSE)). GEOS (LGPL), JTS (EPL/EDL), Boost (BSL), Clipper2
(BSL) and any other project can copy cases into their own test suites without asking and
without attribution. The generator code in [`generators/`](generators/) is code, and like the
rest of the repository it is MIT-licensed ([../LICENSE](../LICENSE)).

## Layout

| path | what |
|---|---|
| [`MANIFEST.json`](MANIFEST.json) | every tier file with its sha256, byte size and case count, and the parameters that made it (`geotruth corpus verify` checks it) |
| [`cases/core/`](cases/core/) | **core tier** (v2, in git): a stratified, deterministic 200 cases per family, 17 families, 3400 cases |
| [`cases/curated.jsonl`](cases/curated.jsonl) | **curated tier** (v2, in git): the minimal case of every triaged finding and documented lead, with provenance and upstream status |
| `cases/full/` | **full tier** (v2, not in git, a release asset listed in the MANIFEST): 1000 cases per family, seed 1 |
| [`cases/seed.jsonl`](cases/seed.jsonl) | the 1000-case v1 smoke-test corpus of the bug hunt: 4 near-degenerate families × 250 (`generators/seed.py 250 1`) |
| [`curated/leads.toml`](curated/leads.toml) | the source of the curated leads: documented candidate bugs without a `findings/` directory yet |
| [`expected/`](expected/) | expected answers, version 2: the engine's exact answer to every case of the core, curated and full tiers, with their manifest ([README](expected/README.md)) |
| [`expected-v1/`](expected-v1/) | expected answers, version 1: the legacy answers of the audited oracle (see below) |
| [`generators/`](generators/) | the case generators, v1 and v2, and the tier builder ([README](generators/README.md)) |
| [`SHA256SUMS`](SHA256SUMS) | checksums of every tracked case and expected-answer file |

The oracle review's own case families are generated by
[`tools/oracle_review/gen_review.py`](../tools/oracle_review/gen_review.py), and Clipper2's
integer cases live with that adapter in
[`adapters/clipper2/int_cases.jsonl`](../adapters/clipper2/int_cases.jsonl).
[`harness/hunt.sh`](../harness/hunt.sh) gathers all of them for a round.

## Tiers

```sh
geotruth corpus build                  # full (N=1000, seed 1) -> core (200/family) + curated
geotruth corpus build --tier curated   # after editing findings/ or curated/leads.toml
geotruth corpus list [--tier core] [--ids] [--families]
geotruth corpus stats --tier core --by degeneracy,range,types,flags
geotruth corpus verify                 # every present tier file against MANIFEST.json
```

- **core** is drawn from full: strata are (variant class, degeneracy, range, geometry
  types). Every stratum gets one case before any gets two (largest strata first); the rest
  is allocated in proportion (largest remainder); within a stratum cases are taken in
  order of sha256(id). The same parameters give byte-identical files (tested).
- **curated** holds, for every entry of [`../findings/registry.toml`](../findings/registry.toml),
  its minimal cases, and for every lead in [`curated/leads.toml`](curated/leads.toml) its
  cases (the original and the minimised one, with `parent`). Provenance carries the
  library, the triage `status` (all leads are `unreviewed`), `upstream_issue` /
  `upstream_status`, where the lead is documented, and what it was verified on.
- **full** is every generated case; only its checksums are in git.

| family | kind | what |
|---|---|---|
| near-collinear, vertex-on-edge, shared-edge, tiny-transform, sliver-spike, hole-contact, multi-touch, tiling-contact, int-grid, scaled | polygon/polygon | the ten generator families of the bug hunt ([generators/README.md](generators/README.md)) |
| line-line | lines | collinear overlap and containment, collinear touch, T-junctions, endpoint on a vertex, vertex touching or crossing a segment, shared vertices, proper crossings, identical lines split differently |
| line-mod2 | lines | Mod-2 boundary rule: closed lines, endpoints shared by 2, 3 or 4 lines, a closed line with a tail, an endpoint in another line's interior |
| point-geometry | points | a point on a line vertex, segment, endpoint, closed-line endpoint, polygon vertex, edge, hole edge, in the interior, in a hole, outside; equal and duplicate points |
| line-polygon | mixed | a line along an edge (full, sub-segment, overhang, chain), through a vertex, tangent at a vertex, inside touching the boundary, chords, in a hole, the shell as a closed line |
| gc | GeometryCollection | overlapping polygons (union semantics), polygons sharing an edge, polygon + line + point, a line covered by a polygon, nested collections, GC against GC |
| empty | conventions | every empty type and collections of empties, against empties and non-empty geometries; multi-geometries with empty elements; tagged `convention` where an operand is empty |
| invalid-zero-length-line | invalid | lines whose points all coincide (real dimension 0 in RelateNG, invalid for GEOS), alone, in a MultiLineString or a GC |

Every operand of a family not named `invalid-*` is valid by the exact engine
(`geotruth.validity`, GEOS IsValidOp semantics). The v2 families are built on exact
integer lattices; about 10 % of their cases are scaled by 2^±(500..900) (`.extreme`,
range tag `extreme`) and about 15 % rotated in floating point (`.rot`), which turns exact
contacts into ulp-level ones.

## Case format

Cases in `core/`, `curated.jsonl` and `full/` use format v2
([`schemas/case.v2.schema.json`](../schemas/case.v2.schema.json)):

```json
{"id": "line-line-1-000008-t-junction.unit.rot", "family": "line-line",
 "tags": {"degeneracy": "ulp", "range": "normal", "n": 5, "k": 1,
          "types": ["LineString", "LineString"], "variant": "t-junction.unit.rot"},
 "provenance": {"source": "generator", "generator": "corpus/generators/families_v2.py",
                "generator_version": "2", "seed": 1, "n_per_family": 1000},
 "a": {"type": "LineString", "coordinates": [...]}, "b": {...}}
```

Tags are computed from the geometry, exactly
([`generators/casev2.py`](generators/casev2.py)): `degeneracy` is `lattice` when the
operands (or two rings or elements of one operand) meet in an exact degenerate contact
(a vertex on a segment or vertex, a collinear overlap), else `ulp` when a vertex lies
within 4096 ulps of the largest coordinate from a segment it does not touch, else
`generic`; `range` is `extreme` below 1e-150 or above 1e150; `n` counts coordinates; `k`
counts the distinct points where a meets b; `flags` include `convention`, `empty`, `gc`,
`zero-length-line`, `invalid-input`, `mod2`, `curated`, `lead`.

The legacy families' v2 cases are the v1 generator's cases (same ids and coordinates for
the same N and seed); `generators/run_all.py` still writes them in FORMAT-v1
([`harness/FORMAT-v1.md`](../harness/FORMAT-v1.md)) for the old harness, where a case is
`{"id", "family", "a": MULTIPOLYGON, "b": MULTIPOLYGON}` with GeoJSON MultiPolygon
coordinate arrays. Each JSON number is read the way a library reads it: it becomes an
IEEE-754 double first, so an integer literal above 2^53 rounds. The exact answer is the
answer for those doubles, taken as rationals.

## Versioning

- **Cases are immutable.** A published case file is never edited. A fix is a new file or a
  new tier, and `SHA256SUMS` makes accidental edits visible. `MANIFEST.json` names the
  corpus version (2.0.0 for the first v2 tiers) and the generator version; a change to a
  generator that could change a case bumps the generator version and the corpus version.
  The curated tier grows as findings are triaged: a new corpus version each time.
- **Expected answers are versioned separately** from the cases (`expected_version` in
  [`expected/MANIFEST.json`](expected/MANIFEST.json): 2 for the engine's answers, 1 for the
  legacy oracle answers in `expected-v1/`), with errata released as new versions. Every
  claim cites the corpus version, the expected version and the engine version.

### `expected-v1/`: legacy oracle answers

`expected-v1/seed.jsonl` holds the answers of the bug hunt's exact oracle, now vendored as
[`tests/reference/oracle.py`](../tests/reference/oracle.py), for `cases/seed.jsonl`. Each
line is a FORMAT-v1 result line with `"lib": "oracle"`:

- validity (`valid_a`, `valid_b`), the nine named predicates, the six areas as doubles, and
  the exact areas as rational strings under `exact` (`inter`, `diff_ab`, `diff_ba`);
- only `id`, `lib`, `valid_a` and `valid_b` when an input is invalid (nothing else is
  defined then).

It was produced by the oracle at commit `e16e757` (`oracle.py seed.jsonl`), and
re-running the vendored copy reproduces it byte for byte:

```sh
python tests/reference/oracle.py corpus/cases/seed.jsonl | cmp - corpus/expected-v1/seed.jsonl
```

These answers cover polygon/polygon predicates, validity and overlay **areas** only. Full
DE-9IM matrices and exact overlay geometry are in [`expected/`](expected/) (version 2).
